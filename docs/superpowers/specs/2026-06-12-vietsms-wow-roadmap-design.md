## 2. P1 — Webhook callbacks (tính năng đinh, ~2 buổi)

**Bài toán B2B thật:** ngân hàng không muốn poll `GET /v1/sms/{id}` — họ muốn được GỌI khi trạng thái đổi. Đây là phần các SMS gateway thương mại (kể cả của Viettel) đều có, và v1 đang thiếu.

### Thiết kế
- **Đăng ký endpoint:** `POST /v1/webhooks {url, events[]}` → trả `{id, secret}` (secret chỉ hiện 1 lần, lưu BCrypt-hash? KHÔNG — cần raw để ký HMAC → lưu AES? v1 đơn giản: lưu plaintext trong DB, ghi rõ trade-off trong docs; nâng cấp vault là talking point). `GET /v1/webhooks`, `DELETE /v1/webhooks/{id}`, `POST /v1/webhooks/{id}/test` (bắn event mẫu).
- **Events:** `sms.sent`, `sms.delivered`, `sms.failed`, `otp.locked`.
- **Transactional outbox:** `DeliveryWorker` khi đổi trạng thái SMS **ghi `webhook_delivery` row trong cùng transaction** (outbox pattern — không gọi HTTP trong transaction). `WebhookWorker` (@Scheduled riêng) đọc outbox → POST.
- **Bảo mật payload:** header `X-VietSMS-Signature: sha256=<HMAC-SHA256(body, secret)>`, `X-VietSMS-Event`, `X-VietSMS-Delivery-Id`. Docs kèm snippet verify (Java + Python).
- **Retry:** timeout 5s; backoff 1m → 5m → 30m; sau 4 attempt → `DEAD` (dead-letter, xem được qua `GET /v1/webhooks/{id}/deliveries?status=DEAD`).
- **Metrics:** `vietsms_webhook_delivered_total`, `_failed_total`, `_dead_total` + histogram latency.
- **Schema:** V5 = `webhook_endpoint(id, api_key_id FK, url, secret, events, enabled, created_at)`; V6 = `webhook_delivery(id, endpoint_id FK, event_type, payload CLOB/jsonb, status, attempts, next_retry_at, last_error, created_at, delivered_at)`.

### Test
- Unit: HMAC signer (vector cố định), backoff schedule, outbox enqueue đúng event.
- Integration: **MockWebServer** (okhttp) làm receiver — happy path (200), retry path (500→500→200), dead path (4×500), signature đúng với secret.

## 3. P2 — PostgreSQL + Testcontainers (~1 buổi)

- Profile `postgres` (`application-postgres.yml`), **audit 4 migration cũ** về tính portable (đổi identity sang `BIGINT GENERATED BY DEFAULT AS IDENTITY` nếu cần — backlog v1 đã ghi nhận).
- `docker-compose.yml` thêm service `postgres:16-alpine` + healthcheck; app service nhận `SPRING_PROFILES_ACTIVE=postgres`.
- **Testcontainers:** 1 lớp IT chạy full context với Postgres thật (smoke e2e: send SMS → worker chuyển trạng thái → query). CI thêm job chạy nó (GitHub Actions hỗ trợ Docker sẵn).

## 4. P3 — Observability "nhìn thấy được" (~1 buổi)

- `deploy/`: compose mở rộng **prometheus + grafana**, datasource + dashboard provisioning từ JSON committed (panels: throughput SMS/OTP, p95 latency, OTP locked, rate-limit hits, webhook success rate, retry depth).
- **Structured JSON logs** (logstash-logback-encoder) — `requestId` correlation từ AuditFilter chảy vào log.
- README: ảnh chụp dashboard thật (PNG committed) — khoảnh khắc "wow" khi scroll.

## 5. P4 — Load test + con số thật (~1 buổi)

- `deploy/k6/send-load.js`: ramp 0→N VUs, mix send/get/verify, thresholds p95.
- Chạy trên docker-compose (postgres profile), **đo thật**: req/s, p95, error rate; tune HikariCP/batch worker nếu nghẽn; ghi before/after.
- README mục "Performance": con số + phương pháp đo + cấu hình máy. **Tuyệt đối không số bịa.**

## 6. P5 — Live demo công khai (~1 buổi + quyết định hosting)

- Compose production-lite sau reverse proxy (Caddy, auto-HTTPS), Swagger mở, **demo key giới hạn rate chặt** + cron rotate.
- ⚠️ Cần Anh Lan chốt hosting: VPS rẻ (~$4-5/tháng, chủ động) vs free tier (Koyeb/Render — ngủ khi idle, có thể chậm lần đầu mở). Khuyến nghị: VPS rẻ — demo "ngủ" trước mặt recruiter còn tệ hơn không có.
- Lưu ý vị trí: chọn region EU cho gần (Anh Lan đang ở Nga, truy cập quản trị qua VPN ổn).

## 7. P6 (optional) — Câu chuyện scale

Chỉ làm khi P1-P5 đã bóng bẩy: (a) Bucket4j + Redis cho rate limit phân tán; (b) Kafka cho delivery pipeline (outbox → Kafka topic → consumer). Mỗi cái sẽ có plan riêng khi được chọn. Giá trị chính: talking points kiến trúc cho vòng phỏng vấn sâu — kể cả chưa làm, spec này cho thấy đã NGHĨ đến.

## 8. Rủi ro & ràng buộc

| Rủi ro | Xử lý |
|---|---|
| Phá v1 đang xanh | Mọi phase: 54 test cũ là regression gate; feature mới có cờ tắt được (`vietsms.webhooks.enabled`) |
| Webhook gọi HTTP trong transaction → treo DB | Outbox pattern tách ghi & gửi (chính là điểm thiết kế đáng kể nhất P1) |
| SSRF qua URL webhook do client đăng ký | Validate URL: chỉ http/https, chặn IP private/loopback/link-local khi resolve (đã ở Nga + máy cá nhân → bài học allow-lan áp dụng lại) |
| Testcontainers trên máy Windows + CI | Cần Docker Desktop đang chạy local; CI ubuntu có sẵn |
| Số liệu load test phụ thuộc máy | Ghi rõ spec máy đo; không so sánh tuyệt đối |
