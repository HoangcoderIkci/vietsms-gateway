## PHASE 1 — Webhook Callbacks (2 buổi, 7 task)

### Buổi 1.A

#### Task 1: Migration V5+V6 + entities + repositories — **Model: sonnet**
**Files:** `V5__webhook_endpoint.sql`, `V6__webhook_delivery.sql`, `webhook/WebhookEndpoint.java`, `webhook/WebhookDelivery.java`, `webhook/WebhookEndpointRepository.java`, `webhook/WebhookDeliveryRepository.java`, test `WebhookRepositoryTest`

V5 (theo style V1-V4 hiện có, identity portable):
```sql
CREATE TABLE webhook_endpoint (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    api_key_id BIGINT NOT NULL REFERENCES api_key(id),
    url VARCHAR(2048) NOT NULL,
    secret VARCHAR(64) NOT NULL,
    events VARCHAR(255) NOT NULL,            -- CSV: sms.sent,sms.delivered,...
    enabled BOOLEAN NOT NULL DEFAULT TRUE,
    created_at TIMESTAMP NOT NULL
);
CREATE INDEX idx_webhook_endpoint_key ON webhook_endpoint(api_key_id);
```
V6:
```sql
CREATE TABLE webhook_delivery (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    endpoint_id BIGINT NOT NULL REFERENCES webhook_endpoint(id),
    event_type VARCHAR(32) NOT NULL,
    payload CLOB NOT NULL,
    status VARCHAR(16) NOT NULL,              -- PENDING|DELIVERED|FAILED|DEAD
    attempts INT NOT NULL DEFAULT 0,
    next_retry_at TIMESTAMP,
    last_error VARCHAR(512),
    created_at TIMESTAMP NOT NULL,
    delivered_at TIMESTAMP
);
CREATE INDEX idx_webhook_delivery_due ON webhook_delivery(status, next_retry_at);
```
Entities map 1:1 (enum `WebhookEventType {SMS_SENT("sms.sent"),...}`, enum `DeliveryStatus`), repo có:
`List<WebhookDelivery> findTop50ByStatusAndNextRetryAtBeforeOrderByNextRetryAtAsc(String status, Instant now)` và `List<WebhookEndpoint> findByApiKeyIdAndEnabledTrue(Long apiKeyId)`.
**Acceptance:** `mvn -q verify` xanh (54 cũ + repo test mới: save/find roundtrip cả 2 bảng, index dùng được qua query method). **Escalation:** → opus.

#### Task 2: HmacSigner + WebhookEventFactory — **Model: sonnet**
**Files:** `webhook/HmacSigner.java`, `webhook/WebhookEventFactory.java`, tests
- `HmacSigner.sign(byte[] body, String secret)` → `"sha256=" + hex(HMAC-SHA256)`. Test với vector cố định: secret `test-secret`, body `{"a":1}` → giá trị tính trước bằng tay trong test (subagent tự tính bằng python/openssl và hardcode vào test — ghi cách tính trong comment).
- `WebhookEventFactory.smsEvent(SmsMessage, WebhookEventType)` → JSON payload chuẩn: `{event, deliveryId?, timestamp, data:{id, to(masked như audit hiện có), status, clientMessageId}}` — tái dùng masking util sẵn có nếu có, không log full số điện thoại (xem AuditService).
**Acceptance:** unit test vector HMAC pass + payload có phone MASKED. **Escalation:** → opus.

#### Task 3: CRUD endpoints + SSRF guard — **Model: sonnet**
**Files:** `webhook/WebhookController.java`, `webhook/WebhookService.java`, `webhook/UrlValidator.java`, DTOs, tests
- `POST /v1/webhooks {url, events[]}` → 201 `{id, secret}` (secret random 32 hex, CHỈ trả lần này); `GET /v1/webhooks` (không lộ secret); `DELETE /v1/webhooks/{id}` (chỉ chủ key); `GET /v1/webhooks/{id}/deliveries?status=`.
- `UrlValidator`: chỉ http/https; resolve host → reject loopback/private/link-local (`InetAddress.isLoopbackAddress/isSiteLocalAddress/isLinkLocalAddress`) → 422 `WEBHOOK_URL_INVALID` (thêm vào docs/error-codes.md).
- Swagger `@ApiResponses` theo style các controller hiện có. Max 5 endpoint/key → 409.
**Acceptance:** MockMvc tests: đăng ký ok, secret chỉ xuất hiện 1 lần, URL `http://127.0.0.1/x` và `http://192.168.1.1/x` bị 422, key khác không xóa được endpoint của nhau (403/404). **Escalation:** → opus.

### Buổi 1.B

#### Task 4: Outbox enqueue trong DeliveryWorker — **Model: OPUS (main session, KHÔNG dispatch)**
Điểm thiết kế nhạy nhất: sửa `DeliveryWorker` để mỗi transition (SENT/DELIVERED/FAILED) **ghi webhook_delivery trong CÙNG transaction** với update trạng thái SMS (outbox). Không gọi HTTP ở đây. Service `WebhookOutbox.enqueue(apiKeyId, eventType, payload)` — tra endpoints enabled theo key + event, tạo PENDING rows (next_retry_at = now). Cờ `vietsms.webhooks.enabled=true` (Configuration table README).
**Acceptance:** test transactional: transition trong worker → rows xuất hiện atomically; tắt cờ → không rows; 54 test cũ + `DeliveryWorkerRetryTest` vẫn xanh nguyên.

#### Task 5: WebhookWorker — gửi + retry/backoff + DEAD — **Model: OPUS (tiếp)**
`WebhookWorker` @Scheduled(1s): claim batch PENDING due (query Task 1), POST qua `RestClient` timeout 5s, headers `X-VietSMS-Signature/Event/Delivery-Id`; 2xx → DELIVERED; lỗi → attempts++, next_retry = now + [1m,5m,30m][attempts-1]; attempts≥4 → DEAD + last_error. Metrics 3 counter + 1 timer vào `VietsmsMetrics` theo style 9 counter hiện có.
**Acceptance (MockWebServer):** happy 200; retry 500→500→200 với backoff đúng lịch (inject Clock như DeliveryWorker đã làm); dead sau 4×500; signature verify được bằng HmacSigner.

#### Task 6: `POST /v1/webhooks/{id}/test` + docs — **Model: sonnet**
Bắn event mẫu `webhook.test` qua đường outbox thật. Docs: section mới trong README + `docs/webhooks.md` (flow diagram mermaid — **label có ký tự đặc biệt phải bọc ngoặc kép**, validate mermaid.ink trước khi commit) + snippet verify chữ ký Java & Python + bổ sung error-codes.md.
**Acceptance:** integration test endpoint test; mermaid HTTP 200 qua mermaid.ink; README Configuration table có cờ mới. **Escalation:** → opus.

#### Task 7: Review chéo Phase 1 — **Model: OPUS (orchestrator)**
Đọc toàn bộ diff P1, chạy `mvn verify` + smoke tay: đăng ký webhook bằng curl → gửi SMS → nhận callback trên MockWebServer/local receiver, verify chữ ký. Cập nhật CHANGELOG.
